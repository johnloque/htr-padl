# N2 — Une case, un appel, prompts spécialisés

Transcrit chaque **case** du registre par un appel de modèle séparé, avec un prompt et un schéma JSON propres au type de colonne. Contexte minimal : moins d'inventions et de boucles qu'en N0/N1, au prix d'un nombre d'appels élevé (≈ 14 par ligne).

- Code : `src/htr/strategies/n2.py` (stratégie) et `src/htr/classifier/categorie.py` (classifieur du symbole de catégorie médicale)
- Configuration par modèle : `configs/N2/<modele>.yaml` ; description des cases : `configs/N2/cells.yaml`
- Prompts : `configs/prompts/n2/` ; vocabulaires fermés : `configs/vocab.yaml`
- Prérequis : la segmentation (`docs/segmentation.md`) doit avoir produit `data/segmentation/<photo>.json` (statut `ok`) et les crops `data/cells/<photo>/rNN/<colonne>.jpg`. Une page non segmentée ou signalée est sautée, avec un avertissement.

## Vue d'ensemble

```
pour chaque ligne rNN, pour chaque colonne :
  crop de la case (agrandi ×2) [+ demi-ligne en contexte]
    ─► prompt = en-tête commun + consigne de la colonne (+ valeurs autorisées)
    ─► appel du modèle, sortie contrainte par un schéma JSON (enum pour les champs fermés)
    ─► texte long : détection de boucle / troncature ─► nouvelles tentatives
    ─► champs recomposés dans le schéma commun (src/htr/schema.py)
```

## 1. Prompts

Chaque prompt est assemblé à partir de deux fichiers :

- `_entete.fr.txt` : contexte (registre de sanatorium, années 1930) et règles communes : transcrire sans corriger, ne pas deviner, case vide → `""`, ignorer le texte qui déborde des cases voisines. Il contient deux emplacements :
  - `{image}` : description de l'image envoyée, prise dans la config (`prompts.image_seule` ou `prompts.image_contexte` selon la variante) ;
  - `{consigne}` : la consigne de la colonne.
- `<colonne>.fr.txt` : ce que contient la case et le JSON attendu. Pour les champs fermés, la liste des valeurs autorisées de `configs/vocab.yaml` est ajoutée automatiquement à la fin de la consigne.

Le prompt complet envoyé pour chaque colonne est enregistré dans `results/runs/N2/<modele>.json` (`config.prompts_used`).

## 2. Les cases

| Colonne | Champs JSON demandés | Type |
|---|---|---|
| `numero` | `numero` | numérique |
| `noms_prenoms` | `nom`, `prenoms` | texte court (nom en haut, prénoms dessous) |
| `profession` | `profession` | texte court |
| `naissance` | `date_naissance` (JJ/MM/AAAA), `lieu_naissance`, `departement_naissance`, `pays` | date + texte court |
| `etat_civil` | `etat_civil` | fermé |
| `admis_au_titre_de` | `organismes` (liste, fermé), `complement` | fermé + libre, recomposés en « organisme et organisme complément » |
| `venant_de` | `venant_de` | texte court |
| `religion` | `religion` | fermé |
| `adresse` | `adresse` | texte long |
| `categorie_medicale` | `categorie_medicale` (P / O) | fermé — modèle ou classifieur |
| `date_entree`, `date_sortie` | une date chacune | date |
| `nb_journees` | `nb_journees` | numérique |
| `observations` | `observations` | texte long |

`num_predict` (longueur maximale de sortie) est fixé par case dans `cells.yaml`.

## 3. Champs fermés

Les valeurs autorisées (`configs/vocab.yaml`) sont imposées par un `enum` dans le schéma JSON, ce qui rend toute autre valeur impossible ; `""` reste toujours autorisé pour une case vide. « Admis au titre de » combine une liste d'organismes (fermée) et un complément libre (département ou ville).

## 4. Texte long (adresse, observations)

Section `long_text` de la config :

- **Longueur proportionnelle à la largeur** : `num_predict = max(num_predict, num_predict_per_100px × largeur du crop / 100)`.
- **Détection de boucle** : un n-gramme de mots (`ngram: 3`) répété plus de `max_repeats` fois (2), ou une sortie tronquée (`done_reason = length`).
- **Nouvelles tentatives** : en cas de problème, les jeux de paramètres de `retries` sont essayés dans l'ordre (température, `repeat_penalty`, `seed` différents). On garde la première réponse sans problème, sinon la première obtenue. Chaque essai raté est noté dans les `warnings` du run.

## 5. Catégorie médicale : modèle ou classifieur

Option `categorie_medicale` de la config :

- `vlm` : appel de modèle comme pour les autres cases ;
- `classifier` : petit classifieur d'images, sans modèle de langage (`configs/N2/classifier.yaml`). Binarisation de Sauvola, retrait des réglures et des pointillés, isolement du symbole (plus grande composante d'encre et ses voisines), descripteur HOG sur un carré de 64 px, vote des k = 3 plus proches voisins (distance cosinus). Il est entraîné sur les cases du gold **sans la photo traitée** (validation croisée par photo) : aucune fuite de la référence.

Exactitude du classifieur seul, en validation croisée : `uv run python -m htr.classifier.categorie`.

## 6. Variantes

Trois configs par modèle (qwen3-vl-8b, gemma3-12b, churro-3b) :

| Config | Différence |
|---|---|
| `<modele>` | case seule ; catégorie médicale par le modèle |
| `<modele>-classif` | catégorie médicale par le classifieur |
| `<modele>-ctx` | la demi-ligne qui contient la case est jointe comme seconde image de contexte |

`-classif` partage le cache de la variante de base (seule la catégorie médicale change) : il ne coûte presque rien une fois la base calculée. `-ctx` a son propre cache.

## 7. Lancer le run

Tous les modèles et variantes, un modèle chargé à la fois, puis l'évaluation :

```bash
caffeinate -i scripts/run_benchmark.sh N2 qwen3-vl-8b qwen3-vl-8b-classif gemma3-12b gemma3-12b-classif churro-3b churro-3b-classif churro-3b-ctx qwen3-vl-8b-ctx gemma3-12b-ctx >> results/logs/N2_benchmark.log 2>&1
```

- `caffeinate -i` empêche la mise en veille du Mac (le garder branché).
- Progression : `tail -f results/logs/N2_benchmark.log`.
- Durée indicative sur M1 Pro 16 Go : ≈ 15 min par photo pour churro-3b, ≈ 27 min pour qwen3-vl-8b ; plus de 30 h pour l'ensemble.

Un seul modèle, ou un essai sur quelques photos :

```bash
uv run python -m htr.run --strategy N2 --model qwen3-vl-8b [--limit 2]
uv run python -m eval.evaluate --only N2/qwen3-vl-8b
```

Attention : `--limit` réécrit `transcripts/N2/<modele>/all.csv` et `results/runs/N2/<modele>.json` avec les seules photos traitées.

## 8. Reprendre après une interruption

Chaque réponse du modèle est ajoutée à `data/cache/N2/<cache>.jsonl` dès sa réception. Un appel identique (même prompt, mêmes images, mêmes paramètres) est ensuite relu dans le cache au lieu d'être recalculé. Une interruption ne fait donc perdre que l'appel en cours.

Pour reprendre, relancer **la même commande** :

```bash
caffeinate -i scripts/run_benchmark.sh N2 qwen3-vl-8b qwen3-vl-8b-classif gemma3-12b gemma3-12b-classif churro-3b churro-3b-classif churro-3b-ctx qwen3-vl-8b-ctx gemma3-12b-ctx >> results/logs/N2_benchmark.log 2>&1
```

Les modèles déjà terminés repassent en quelques secondes (tout vient du cache) ; on peut aussi les retirer de la liste. Les transcriptions et le fichier de run du modèle repris sont reconstruits en entier. Une dernière ligne de cache tronquée par un arrêt brutal est ignorée au chargement.

## 9. Comparer des versions alternatives des prompts

1. Créer un dossier, par exemple `configs/prompts/n2_v2/`, et n'y mettre **que les fichiers modifiés**, sous le même nom que dans `configs/prompts/n2/` (y compris `_entete.fr.txt`). Les fichiers absents gardent la version par défaut.
2. Lancer avec `--prompts` (ou la variable `PROMPTS` pour le script) :

   ```bash
   uv run python -m htr.run --strategy N2 --model qwen3-vl-8b --prompts configs/prompts/n2_v2
   PROMPTS=configs/prompts/n2_v2 scripts/run_benchmark.sh N2 qwen3-vl-8b gemma3-12b-classif
   ```

3. Les sorties sont nommées `<modele>@<nom du dossier>` (ou `--tag <nom>`) : `transcripts/N2/qwen3-vl-8b@n2_v2/`, `results/runs/N2/qwen3-vl-8b@n2_v2.json`. `uv run python -m eval.evaluate` les compare directement aux versions par défaut.

Le cache est partagé avec la version par défaut : seules les colonnes dont le prompt a changé sont recalculées. Modifier `_entete.fr.txt` change tous les prompts, donc tout est recalculé. Le fichier de run garde le dossier utilisé (`prompts_dir`) et le texte complet de chaque prompt (`config.prompts_used`), ce qui permet de retrouver ce qui a été comparé même après avoir réédité les fichiers.

## 10. Sorties

- `transcripts/N2/<modele>/<photo>.csv` et `all.csv` : une ligne par patient, schéma commun
- `results/runs/N2/<modele>.json` : config, prompts envoyés, temps, tokens, mémoire, validité JSON et avertissements par photo
- `data/cache/N2/<cache>.jsonl` : réponses brutes avec tous les paramètres d'appel
- après `eval.evaluate` : `results/metrics.csv`, `summary.csv`, `errors.csv`, `summary.md`
